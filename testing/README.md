# Module de Validation & Test Logiciel

Ce dossier regroupe mes exercices pratiques et cas d'étude réalisés dans le cadre de ma formation et de mon autoformation en **Testing Logiciel**. Chaque section présente la démarche théorique suivie ainsi que l'exercice correspondant.

---

## 1. Stratégie & Planification de Test

* **Concept :** Définir le cadre d'une campagne de test, la stratégie globale, la couverture des exigences, les critères d'entrée/sortie et la gestion des risques.
* **Exercice correspondant :** [`/plans-de-test/Live-Project_Test-Plan_SoftwareTestingHelp.pdf`](./plans-de-test/Live-Project_Test-Plan_SoftwareTestingHelp.pdf)
  * *Description :* Étude d'un plan de test réel pour le module RH (OrangeHRM)[cite: 13, 17]. Ce document détaille les niveaux de test (Exploratoire, Fonctionnel, UAT), les stratégies d'exécution et les critères d'acceptation[cite: 15, 19, 21].

---

## 2. Conception des Cas de Test

* **Concept :** Analyser les exigences fonctionnelles pour concevoir des cas de test détaillés (préconditions, jeux de données, étapes, résultats attendus).
* **Exercice correspondant :** [`/cahiers-de-test/test logiciel -Conception des tests.pdf`](./cahiers-de-test/test%20logiciel%20-Conception%20des%20tests.pdf)
  * *Description :* Exercice pratique de conception de cas de test pour l'accès aux interfaces et marketplaces (ex: Marketplaces membres et privées)[cite: 11, 12].

---

## 3.  Exécution des Tests & Bilan de Campagne

* **Concept :** Exécuter les cas de test, consigner les résultats (Pass / Fail / Non Testé) et calculer les indicateurs de couverture et de complétude.
* **Exercice correspondant :** [`/cahiers-de-test/exemple_de_bilan_de_test.xlsx`](./cahiers-de-test/exemple_de_bilan_de_test.xlsx)
  * *Description :* Cahier d'exécution et tableau de synthèse mesurant la couverture des tests (Authentification, Pages Web, CSS) avec calcul automatique du taux d'avancement[cite: 3].

---

## 4. Gestion & Documentation des Anomalies

* **Concept :** Identifier un écart entre le résultat attendu et le résultat obtenu, puis documenter l'anomalie de façon claire pour l'équipe de développement.
* **Exercices correspondants :**
  * [`/anomalies/test logiciel -Exécution des tests.pdf`](./anomalies/test%20logiciel%20-Ex%C3%A9cution%20des%20tests.pdf) (Cas d'exécution sur le parcours d'achat Vente Flash)[cite: 33, 34].
  * [`/anomalies/test logiciel -Créationn d'une anomalie.pdf`](./anomalies/test%20logiciel%20-Cr%C3%A9ationn%20d'une%20anomalie.pdf) (Fiche de bug détaillée pour impossibilité de paiement CB)[cite: 35].

---

## 5. Test d'APIs REST

* **Concept :** Valider les endpoints d'une API web (méthodes HTTP, paramètres de requête, corps JSON et codes de statut HTTP).
* **Exercices correspondants :**
  * [`/api-testing/EXERCICE api.pdf`](./api-testing/EXERCICE%20api.pdf) (Matrice des routes API des employés : GET, POST, PUT, DELETE)[cite: 5].
  * [`/api-testing/EXERCICE api - analyser.pdf`](./api-testing/EXERCICE%20api%20-%20analyser%20.pdf) (Analyse de requêtes et réponses JSON sous Postman)[cite: 6, 7].
