# 🌐 Validation & Tests d'APIs REST

## 📌 Contexte & Objectif

Dans le cadre de mon parcours d'apprentissage, j'ai étudié la structuration des cas de test d'API REST (méthodes HTTP, verbes CRUD et analyse des réponses).

## 🔑 Points Essentiels Abordés

* **Méthodes HTTP & CRUD :**
  * `GET` : Récupération de ressources.
  * `POST` : Création de données (envoi d'un corps JSON).
  * `PUT` : Mise à jour de ressources.
  * `DELETE` : Suppression de données.

* **Analyse des Réponses API :**
  * Validation des codes de statut HTTP (`200 OK`, `201 Created`, `400 Bad Request`, `404 Not Found`).
  * Inspection des en-têtes (*Headers*), des paramètres d'URL (*Query Params*) et de la structure des charges utiles (*JSON Body*).

> ℹ️ **Note :** Ce module formalise l'assimilation des concepts et de la méthodologie de test d'API REST. Les manipulations pratiques sur des outils comme Postman constitueront la prochaine étape de ma montée en compétences lors de la POEI.

## 💡 Ce que j'ai appris & Liens avec mon parcours

* **Validation sous la surface (Back-end) :** Le test d'API permet de vérifier la logique métier et la conformité des données échangées avant même l'existence d'une interface graphique (UI).
* **Rigueur analytique :** Vérifier qu'un JSON renvoie exactement les paires clé/valeur attendues s'apparente au contrôle de conformité des spectres ou des données brutes en chimie.
