# 📋 Stratégie & Planification de Test (Plan de Test OrangeHRM)

## 📌 Context & Objectif de l'exercice
Analyse et appropriation d'un plan de test réel (*Master Test Plan*) sur le module **My Info** de l'application RH **OrangeHRM**. L'objectif était de comprendre comment cadrer une campagne de recette complète avant la phase d'exécution.

## 🔑 Points essentiels abordés
* **Niveaux et types de test :**
  * *Exploratory Testing* : Validation rapide de la stabilité de l'application avant les campagnes formelles.
  * *Functional Testing* : Vérification systématique des fonctionnalités par rapport aux spécifications.
  * *User Acceptance Testing (UAT)* : Validation métier finale réalisée avec les utilisateurs clés.
* **Critères d'entrée et de sortie (*Entry/Exit Criteria*) :**
  * *Entrée* : Spécifications validées, environnement déployé, jeux de données prêts.
  * *Sortie* : 100 % des tests exécutés, 95 % de taux de réussite, 0 anomalie critique/bloquante ouverte.
* **Gestion des risques & Contingences :** Identification des risques projet (décalages de planning, indisponibilité de l'environnement) et définition de plans d'atténuation.

## 💡 Ce que j'ai appris & Liens avec mon parcours
* **Rigueur de cadrage :** Un test sans planification claire expose le projet à des oublis majeurs.
* **Analogie avec la chimie :** Tout comme un protocole de laboratoire définit le matériel, les conditions opératoires et les critères de conformité avant l'essai, le plan de test définit l'environnement, les critères d'entrée/sortie et les responsabilités avant la recette.
